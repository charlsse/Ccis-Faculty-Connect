# Notification schema review

The explicitly selected main migration `2026_11_20_000000_add_payment_notification_delivery.php` adds six notification-delivery fields to `water_notices`: a nullable unique event key, optional context, email state/attempt count, next-attempt time and delivered time. Existing notice contents and read states are retained. It does not modify users, payments, collections, receipts, credentials, gateway configuration or database connections. Defaults do not queue historical notices for email.

The explicitly selected demo migration `database/demo/002_create_notification_outbox.php` adds a new notification-event table to the existing SQLite demo ledger. Its primary key deduplicates logical terminal payment events. It contains no balances or actual settlement. Events commit with the demo attempt; delivery into the main notices table is independent, recoverable and deduplicated. No historical schema is dropped. Rollbacks refuse to discard notification history automatically.

Review evidence before installation: the migrations and delivery paths passed 130 focused tests / 1,551 assertions, including rollback, cross-database delivery failure and recovery, repeated webhooks, owner scope, manual review, receipt uniqueness, reminder deduplication, and email transport failure/retry. PHP tests use the guarded SQLite in-memory databases and provider/mail fakes. Main financial and account fingerprints are checked before/after the additive installation. The existing protected backup runner supplies a new main-database backup; SQLite is backed up with VACUUM INTO. Only the named migration is run; no broad pending migration batch or destructive production migration is authorized.

Deployment after explicit approval: both exact migrations were applied after a fresh protected backup was successfully restored to an isolated schema. Both migration records, indexes and event-key constraints were verified. The post-deployment full suite passed 224 tests / 2,283 assertions. Ten protected main tables, existing demo attempts and original notice/read-state fingerprints remained unchanged. Actual in-app delivery/replay checks passed; email remains disabled. See `notification-deployment-completion-report.md` for evidence and remaining limitations.
